1. Project Overview

FixLink is a full-stack Smart-Room Maintenance Tracker built for MIT-WPU's Vyas Building. It enables students and faculty to report infrastructure issues (broken ACs, plumbing leaks, electrical faults, etc.) for specific rooms, and provides administrators a real-time dashboard to manage, assign, and track maintenance tickets through their entire lifecycle.

Key Features

Feature Description
Maintenance Ticketing Students/faculty submit issues via a visual room-map interface. Tickets track status from open → assigned → in-progress → fixed.
Interactive Floor Maps SVG-based room maps with color-coded statuses (red = issue, yellow = in-progress, blue = assigned, green = normal).
Professional Management Certified maintenance workers (electricians, plumbers, IT technicians, carpenters) receive assignments, start/complete jobs, and upload proof-of-fix photos.
Real-Time Notifications Pusher-powered live updates push ticket changes, chat messages, and help requests to admin and professional dashboards instantly.
Faculty Room Scheduling Faculty members can view timetables, book vacant rooms on-the-fly, and track room occupancy in real time.
Analytics & Predictive Maintenance Asset health scoring (0–100), technician efficiency metrics (MTTR, completion rate), and ticket volume trends.
QR Code Entry Each room has a printable QR code linking directly to its report page (/report?room=VY404).
Email Notifications Automated emails via EmailJS for ticket creation, status updates, account verification, and password resets.
Web Push Notifications Native browser push notifications via the Web Push API and VAPID keys for urgent alerts.
Super Admin Panel A developer-level dashboard for managing admin accounts, faculty, and professionals.

3. Architecture Overview

FixLink follows the Flask Application Factory Pattern with a modular Blueprint architecture.

┌──────────────────────────────────────────────────────────────┐ │ VERCEL EDGE │ │ ┌─────────────────────────────────────────────────────────┐ │ │ │ api/index.py → create_app() → Flask WSGI App │ │ │ └──────────────────────┬──────────────────────────────────┘ │ └─────────────────────────┼────────────────────────────────────┘ │ ┌───────────────┼───────────────┐ ▼ ▼ ▼ ┌─────────────┐ ┌──────────┐ ┌──────────────┐ │ Blueprints │ │ Cache │ │ Database │ │ (6 modules) │ │ /tmp/ │ │ (Supabase) │ └─────────────┘ └──────────┘ └──────────────┘ │ ┌──────┴───────────────────────────────┐ │ │ ▼ ▼ ▼ ┌────────┐ ┌──────────────┐ ┌────────────┐ │ EmailJS│ │ Pusher │ │ Web Push │ │ REST │ │ WebSocket │ │ (VAPID) │ └────────┘ └──────────────┘ └────────────┘

Application Factory (app/__init__.py)

The create_app() function: 1. Loads environment variables and configures secrets 2. Sets up Vercel-specific session security (secure cookies, proxy headers) 3. Configures the PostgreSQL connection with NullPool on Vercel (prevents stale connections) 4. Initializes extensions: SQLAlchemy, Flask-Migrate, Flask-Caching, CSRF, Rate Limiter 5. Runs database initialization via init_db(app) 6. Registers all 6 blueprints 7. Starts the background scheduler (disabled on Vercel) 8. Registers Jinja2 filters (IST timezone formatter)

6. Authentication & Authorization

Authentication Flow

FixLink uses a unified login page (/login) that supports three types of users:

  1. Students/Faculty — Login with MIT-WPU email + password
  2. Professionals — Login with username, phone number, or email + password
  3. Super Admin — Login at /developer/login with environment-configured credentials

Session Management

  • Sessions are stored in cryptographically signed Flask cookies using SECRET_KEY
  • On Vercel, cookies are configured with Secure, HttpOnly, SameSite=Lax
  • Session lifetime: 1 hour (PERMANENT_SESSION_LIFETIME=3600)
  • No per-request DB validation — sessions are trusted after login (optimized for serverless latency)

Authorization Decorators (decorators.py)

Decorator Required Session Key Description
@login_required user_id OR professional_id Any authenticated user
@user_login_required user_id Students, faculty, or admins
@admin_required user_id + is_admin=True Admin-only routes
@faculty_login_required user_id + role=faculty (or admin) Faculty dashboard
@professional_login_required professional_id Professional dashboard
@super_admin_required is_super_admin=True Developer panel

All decorators support AJAX requests by returning 401 JSON instead of redirecting when the request has X-Requested-With: XMLHttpRequest.

Email Verification Flow

  1. User signs up → account created with is_verified=False
  2. Verification email sent via EmailJS with a time-limited token
  3. User clicks link → confirm_verification_token() validates the token
  4. User is directed to set their password → is_verified=True

Password Reset Flow

  1. User requests reset → send_password_reset_email() sends link via EmailJS
  2. Token generated with itsdangerous.URLSafeTimedSerializer (1-hour expiry)
  3. User clicks link → sets new password

8. API Integrations

8.1 EmailJS (Transactional Email)

Module: app/utils.py
API Endpoint: https://api.emailjs.com/api/v1.0/email/send
Authentication: Service ID + Public Key + Private Key (via accessToken)

EmailJS is used as a serverless-friendly email delivery mechanism (no SMTP server needed).

Functions:

Function Trigger Email Content
send_ticket_email(ticket, action) Ticket created, in-progress, or fixed Status update to reporter
send_verification_email(email, name, link) User signup Account verification link
send_password_reset_email(email, name, link) Forgot password Password reset link

Payload Format: json { "service_id": "service_xxxxx", "template_id": "template_xxxxx", "user_id": "public_key", "accessToken": "private_key", "template_params": { "to_email": "user@mitwpu.edu.in", "to_name": "Student Name", "subject": "FixLink Ticket #42 Received", "message": "Your maintenance request has been received..." } }

Graceful Degradation: If any EmailJS env vars are missing, the functions log a warning and return False without crashing.

8.3 Web Push API (VAPID)

Module: app/utils.py → send_web_push()
Library: pywebpush

Native browser push notifications for urgent alerts (overdue tickets, unassigned tickets, asset health).

Setup: 1. Generate VAPID keys: python scripts/generate_vapid.py 2. Store VAPID_PRIVATE_KEY and VAPID_SUBJECT in environment 3. Frontend registers a Service Worker (app/static/js/sw.js) that subscribes to push 4. Subscription saved to push_subscriptions table via /api/subscribe-push

Push Payload: json { "title": "Overdue Ticket Alert", "body": "Ticket #42 (Room VY404) is past its deadline!", "url": "/admin/?ticket_id=42" }

8.4 Supabase PostgreSQL

Connection: Standard PostgreSQL connection string
Driver: psycopg2-binary

Connection Pooling: - Vercel: Uses NullPool — each request opens and closes its own connection (prevents stale connections across cold starts) - Local/Docker: Uses connection pool with pool_size=5, pool_recycle=300, pool_pre_ping=True

SSL: Auto-appends sslmode=require on Vercel if not present.

10. Caching Strategy

Module: app/cache.py
Backend: FileSystemCache (Vercel: /tmp/fixlink_cache, Local: app/.cache)

Why FileSystemCache?

Vercel serverless functions run in isolated instances. In-memory caches (SimpleCache) are lost on every cold start and are not shared between instances. The /tmp/ directory on Vercel persists across warm function invocations and is shared more reliably.

Cached Data

Cache Key Pattern TTL Data Used By
map_floor_{floor_id} 1 hour Room list with status, occupancy, tickets Report form, Status map
admin_floor_{floor_id} 1 hour Admin-specific floor data Admin map view

Cache Invalidation

Function When Called
invalidate_floor_cache(floor_id) Ticket created/updated, asset status changed
invalidate_all_map_cache() Nuclear option — clears everything

Eager Loading

The get_cached_floor_data(floor_id) function uses SQLAlchemy joinedload to prevent N+1 queries: python rooms = Room.query.options( joinedload(Room.tickets), joinedload(Room.assets), joinedload(Room.room_bookings).joinedload(RoomBooking.faculty), joinedload(Room.timetables).joinedload(Timetable.faculty) ).filter_by(floor_id=floor_id).all()

11. Background Scheduler

Module: app/scheduler.py
Runs: Every 30 minutes in a daemon thread
Disabled on: Vercel (serverless cannot maintain background threads)

Alert Types

Alert Condition Recipient Cooldown
Unassigned Ticket open or cancelled for >24 hours All admins 24 hours
Overdue Ticket Past deadline_datetime, not fixed/cancelled All admins 12 hours
Professional Inactivity in-progress for >4 hours Assigned professional 4 hours
Critical Asset Health Health score <30% All admins Per run

Each alert is sent as a Web Push notification and uses last_notification_sent_at on the ticket to prevent duplicate alerts.

12. Analytics Engine

Module: app/analytics.py

Asset Health Score (0–100)

Formula: Score = 100 - (Age in years × 5) [Lifecycle depreciation] - (50 if broken, 20 if maintenance) [Current status] - (Recent tickets × 10) [Repair frequency, last 60 days] - (10 per high-complexity ticket, 5 per medium) [Complexity penalty]

Technician Efficiency Metrics

Metric Calculation
MTTR (Mean Time to Repair) Average (fixed_at - job_started_at) in hours
Completion Count Total tickets with status=fixed
Active Load Current assigned or in-progress tickets

System Trends

Ticket volume over the last N days, returned as {labels: [...dates], values: [...counts]} for Chart.js rendering.

Critical Assets

Batch-processes all assets with optimized queries (no N+1), returns the top N lowest-scoring assets.

Entry Point: api/index.py → Exports a WSGI app object.

Configuration (vercel.json): json { "builds": [{ "src": "api/index.py", "use": "@vercel/python", "config": { "maxDuration": 30 } }], "headers": [{ "source": "/static/(.*)", "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }] }], "routes": [{ "src": "/(.*)", "dest": "/api/index.py" }] }

Key Vercel Behaviors: - All routes funnel through the single Python serverless function - Static assets (/static/*) are cached for 1 year at the Edge CDN - NullPool is used for database connections (no persistent pool) - Background scheduler is disabled (serverless cannot maintain threads) - File uploads are skipped (read-only filesystem; would need Supabase Storage) - Database initialization/seeding is skipped (assumed pre-migrated)

Local Development

```bash

git clone https://github.com/meowpher/FixLink-V1.git cd FixLink-V1

2. Create virtual environment

python -m venv venv source venv/bin/activate # or venv\Scripts\activate on Windows

3. Install dependencies

pip install -r requirements.txt

4. Configure environment

cp .env.example .env

Edit .env with your Supabase URL, SECRET_KEY, etc.

5. Run

python run.py

→ Serves at http://localhost:5000

```

17. QR Code System

Generator: scripts/generate_qr.py
Output: qr_codes/ directory with PNG files named {Building}_{RoomNumber}_QR.png

Each QR code encodes a URL like: https://your-domain.vercel.app/report?room=VY404

When a student scans the QR code in a room, the report form auto-selects that room, floor, and building — enabling one-tap issue reporting.
